# E-12 — Notifications
**Feature:** F-12 | **Wave:** 2 | **Domain:** NOTIFICATIONS

## Purpose
Multi-channel notifications on leave status changes: in-app (60s Axios polling), email (SendGrid v3 — plain text/inline HTML, no template IDs), and Google Calendar event (company-wide service account — no per-user OAuth2).

## User Stories
| ID | Story |
|----|-------|
| US-12.1 | Employee receives in-app notification on leave status change |
| US-12.2 | Employee receives SendGrid email on approval/rejection |
| US-12.3 | Approved leave creates event on shared Google Calendar |

## Success Criteria
- No SendGrid template ID anywhere in code or config (UT-54)
- Google Calendar uses service account JSON key from env; no per-user consent (UT-55, IT-44)
- Email and calendar tasks enqueued via Hangfire (email: 5 retries/24h; calendar: 3x exp backoff)
- Notification bell badge updates within 60s of event

- Blocks: E-13 (dashboards include notification state)
