# Repository Structure — Leave Management System (LMS)

## Branch Strategy

- **Base branch**: `main` (single-branch — all PRs target main)
- **Feature branches**: `feat/[ISSUE-ID]-[slug]` (Ralph-impl)
- **Test branches**: `test/[ISSUE-ID]-[slug]` (Ralph-test)
- **E2E branches**: `e2e/[ISSUE-ID]-[slug]` (Ralph-e2e)

## PR Conventions

- **Title**: `[ISSUE-ID] [issue title from PMS]`
- **Description**: Paste link to GitHub issue + brief summary of what was implemented + test results
- **Merge strategy**: Squash merge (keep main history clean)
- **CI gate**: All CI checks must pass before merge (build, lint, unit tests, LSP diagnostics)

## Worktree Convention

- Domain-level worktree: `../lms-v5-wt-[domain]` (e.g. `../lms-v5-wt-auth`)
- Issue-level worktree: `../lms-v5-wt-[domain]-[issue-id]` (e.g. `../lms-v5-wt-auth-DB-001`)

## Key Files Every Agent Must Read
1. `CONSTITUTION.md` — non-negotiable engineering law
2. `CLAUDE.md` — session conventions generated by /agile-verify
3. `docs/agile/tasks/T-[N].md` — the specific task being implemented
4. `docs/06_rbac.md` — RBAC enforcement rules
5. `ai-context/architecture.md` — system boundaries + API standards
6. `ai-context/coding-standards.md` — code quality rules from Article II of Constitution
